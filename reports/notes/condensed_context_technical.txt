Older leftout / SVD-aux summary
- `entropyscore_forget` and aux variants now use a left-projected carry:
  - optimize right basis `V_new`
  - form `Y = M_gain V_new`
  - QR-orthonormalize to `U_hat`
  - carry SVD of `U_hat.T @ M_gain`
- The old right-projected claim `||(M P_V) v_i|| <= ||M v_i||` was wrong.
- Safe diagnostic is left-projected:
  - `P_U = U_hat U_hat.T`
  - `||P_U M v_i|| <= ||M v_i||`
- `left_projected_operator_svd_factors` in `utils.py` was patched to use stable reduced QR instead of float32 Gram-Schmidt because bad `U_hat` orthogonality caused catastrophic `sr=8` failures.

Optimizer difference check
- File: `cex_optimizer_first_block_compare.py`
- Purpose: compare first block only, same full row-space basis, same cex restart seeds projected to reduced coordinates.
- Command:
  - `python3 -u cex_optimizer_first_block_compare.py`
- Result:
  - component 1:
    - cex full score `0.8417016216`, `s=0.9179605592`, `H=4.5962382639`
    - utils reduced score `0.8414852919`, `s=0.9178259556`, `H=4.5965258273`
    - alignment `|v_full.T v_red| ~= 0.9751`
  - component 2:
    - cex full score `0.8346551501`, `s=0.9165590028`, `H=4.5538669062`
    - utils reduced score `0.8325121095`, `s=0.9139828117`, `H=4.5780860768`
    - alignment `|v_full.T v_red| ~= 0.7992`
- Core optimizer differences:
  1. cex optimizer steps with raw tangent gradient:
     - `v + alpha * g`
  2. utils reduced optimizer normalizes the gradient direction:
     - `step = gtan / ||gtan||`
     - `z + alpha * step`
  3. cex uses Armijo on score:
     - `score_trial >= score_old + 1e-4 * alpha * g.T @ g`
  4. utils accepts strict log-objective improvement only:
     - `logf_t > logf`
  5. cex optimizes score directly in float64.
  6. utils optimizes log(score) in float32 reduced coordinates.
  7. restart generation differs in normal `main.py`/utils path:
     - cex uses SVD-based structured restarts from `M_gain`
     - utils uses prior vector, coordinate vector, and random reduced vectors.
- Conclusion:
  - `utils.entropy_iter_basis_forget` is not a literal reduced-coordinate version of the cex optimizer.
  - The next best fix is to add a cex-style reduced optimizer using raw reduced gradients, Armijo score condition, progress stopping, cex restart seeds, and preferably float64 for cex tests.

Expansion-direction diagnosis and ablation
- Prior issue:
  - The residual diagnostic measured whether the full-space gradient had energy outside the current reduced basis.
  - But the old expansion action appended the current best vector and its Krylov chain, i.e. `[v_best, A^T A v_best, ...]`.
  - Since `v_best` already lies in the reduced basis, the append often added no new information.
  - This explains why `q0=5, qmax=200, expansion_maxit=64` still stayed at `subspace_dim=5`.
- New expansion mode:
  - `--expansion-direction residual` appends the feasible out-of-basis gradient residual, then its Krylov chain.
  - The residual is tangent-projected against the current vector and previously selected score vectors, then projected outside the current reduced basis.
  - `--expansion-direction krylov_v` preserves the old behavior for reproduction/comparison.

  - `B_gain = M_gain @ Vbasis`, shape roughly `rows_gain x q`
  - `B_block = A_block @ Vbasis`, shape roughly `rows_block x q`
  - `C_prev = prev_basis.T @ Vbasis`, shape roughly `old_rank x q`
  - reduced variable `z in R^q`
- Typical cex middle window with small expansion:
  - `B_gain ~= 102 x q`
  - `B_block ~= 100 x q`
  - `C_prev ~= 2 x q`
  - `q ~= 15-43`
- Final window:
  - `B_gain ~= 26 x q`
  - `B_block ~= 24 x q`
  - `C_prev ~= 2 x q`
- Timed operation profile with `num_restarts=1`, `maxit=120`, residual expansion:
  - total reduced evaluator calls:
    - initial calls `4205`
    - streaming calls `23874`
    - total `28079`
  - representative average times:
    - `B_gain @ z`: `~2.1us`
    - `B_block @ z`: `~2.0us`
    - `B_block.T @ y`: `~2.2us`
    - `B_block.T @ y3`: `~2.1us`
    - `C_prev @ z`: `~1.7us`
    - `C_prev.T @ (...)`: `~2.5us`
    - `sum(y^4)`: `~5.9us`
    - `grad_score_combine`: `~8.7us`
    - `project_reduced`: `~2.2us`
    - `retract_reduced`: `~7.6us`
- Conclusion:
  - Line search really is on small matrices.
  - Individual reduced matrix operations are cheap.
  - Cost comes from many small NumPy calls/temporaries and repeated optimizer iterations/solve batches.

Line-search counter profile
- Armijo was not backtracking heavily:
  - stream iterations `12345`
  - stream line-search trials `12465`
  - average trials per stream iteration `1.0097`
  - initial iterations `1827`
  - initial line-search trials `1827`
  - average trials per initial iteration `1.0`
  - streaming accept at step 1: `12225`
  - streaming accept at step 2: `120`
- Previous implementation issue:
  - line search computed `score_t` by calling full score+gradient evaluator
  - after accepting, code recomputed full score+gradient at the same accepted `z`
  - because most accepts were at first trial, this duplicated almost every per-iteration evaluator call
- Measured eval timing:
  - stream line-search eval time `~0.656s` for `12465` calls
  - stream accepted-gradient eval time `~0.626s` for `12345` calls
  - initial line-search eval time `~0.068s` for `1827` calls
  - initial accepted-gradient eval time `~0.064s` for `1827` calls

Implemented optimizer changes
- In `utils.py`:
  - `basic_projected_ascent_single_reduced_forget_cex(..., reuse_line_search_grad=True)`
  - `basic_projected_ascent_single_reduced_streaming_forget_cex(..., reuse_line_search_grad=True)`
  - accepted Armijo trial now stores `(score_t, grad_t, s_t, H_t)` and reuses it instead of recomputing.
- In `entropy_iter_basis_forget`:
  - new options:
    - `reuse_line_search_grad=True`
    - `expansion_warm_start=False`
    - `post_expansion_maxit=None`
  - when `expansion_warm_start=True` and `z_warm` exists, the lifted previous reduced optimum is used as the first seed after expansion.
  - this avoids regenerating cex SVD seed when `num_restarts=1` and warm start already fills the requested one seed.
  - if `post_expansion_maxit` is set, solve batches after expansion use `min(maxit, post_expansion_maxit)`.
- Exposed in:
  - `main.py`
    - `--reuse-line-search-grad` / `--no-reuse-line-search-grad`
    - `--expansion-warm-start` / `--no-expansion-warm-start`
    - `--post-expansion-maxit`
  - `cex_restricted_space_probe.py`
    - same relevant controls plus `--expansion-direction`
- Defaults after latest change:
  - routine `entropyscore_forget_step` uses `work_dtype=np.float32`
  - `cex_restricted_space_probe.py --dtype` defaults to `float32`
  - `main.py --cex-replicate` still forces `float64`
