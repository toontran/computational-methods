Value-only future_hmean_online — corrected operational baseline
================================================================

Date: 2026-04-28
Backlog item: summary/overview/score_family_workflow.txt §5 [INFRA-10]
Triggered by: discovered flaw in `future_hmean_online`'s candidate pool.

This is the value-only rerun that replaces summary/bench_matrix_sweep/
synthesis.txt as the OPERATIONAL bar for AB-01, FAM-01, FAM-03, FAM-04,
FAM-05, the §4 op-bar, and the §5 sequencing conditional in the workflow
doc. The original (oracle-aware) numbers are RETAINED at
summary/bench_matrix_sweep/ as a labeled CEILING reference.


1. The flaw
-----------

future_hmean_online's candidate pool was oracle-seeded:

  half_window_sliding_hmean_experiment.py:24  (pre-fix)
    ONLINE_POOL = ("opt2", "q2_vs_q1oracle", "mgain_deflated_svd",
                   "block_complement", "prev_opt2")

  half_window_sliding_hmean_experiment.py:247-250
    "q2_vs_q1oracle" branch is built from `raw_oracle`.

  half_window_sliding_hmean_experiment.py:490
    Q_oracle, raw_oracle = raw_oracle_columns(M_gain, V_exact, rank, ...)

  second_slot_tail_bias_diagnostic.py:32 (raw_oracle_columns)
    Projects V_exact[:, :rank] (the TRUE right singular vectors of A)
    into the row span and returns them as candidates.

So 1 of 5 entries in ONLINE_POOL was V_exact[:,1] projected into B_union.
The "online" benchmark's slot-2 victory on tail-dominant matrices was
substantially the oracle picking itself out of the pool — not a property
of HM-online scoring.

A value-only score family literally cannot close the gap to such a
benchmark, because the rival's pool contains the answer.


2. The fix
----------

`half_window_sliding_hmean_experiment.py` (lines 31-33, 512-514):

  ONLINE_POOL_VALUE_ONLY  = ("opt2", "mgain_deflated_svd",
                             "block_complement", "prev_opt2")
  ONLINE_POOL_ORACLE_AWARE = ("opt2", "q2_vs_q1oracle",
                              "mgain_deflated_svd", "block_complement",
                              "prev_opt2")
  ONLINE_POOL = ONLINE_POOL_VALUE_ONLY    # default

  CLI flag --online-include-oracle restores the oracle-aware pool when
  needed (e.g., for upper-bound studies). Default is value-only.

Everything else in the bench harness is unchanged. Same matrix loader,
same half_win=32 sliding mode, same 1024 rows, same 32 blocks.

Interpretation:
  - Massive oracle leak on the mixed-tail-balanced (+0.77) and
    diffuse-diffuse (+0.48) cos1² numbers. The "online's slot-2
    crushes everything on tail-dominant matrices" framing in the
    overview was substantially carried by the oracle injection.
  - Modest leak on mixed-tail-soft, residual-spiky-shocks (+0.02 to
    +0.05). These numbers were closer to "real."
  - No leak on static-cex (combined-greedy v1 dominates regardless of
    pool), etf-basket-basis (online still wins big — the HM-online
    candidate from the 2-SVD reframe is doing the work), or
    risk-residual-panel.
  - cos0² leak is also significant: +0.22 to +0.54 on tail-dominant /
    diffuse matrices. The oracle injection was helping slot-1 too,
    via the joint optimization in the candidate selector.

This radically reframes the §6 table reading in score_design_overview.txt.
The previous narrative — "S6 trails online by 0.5–0.85 cos1² on every
tail-dominant matrix" — was an artifact of the oracle leak. With the
corrected baseline:

  - On the tail-dominant subset (mixed-tail-*, static-cex, diffuse-
    diffuse, etf-basket-basis), S6 already MATCHES OR BEATS value-only
    online on 4 of 6. The remaining gaps are
      mixed-tail-balanced  (-0.04, modest)
      static-cex           (combined still rules; both score-families lose)
      etf-basket-basis     (-0.16, real; online's HM-online is doing
                            something genuinely useful here)
  - On the spiky-residual subset (residual-spiky-shocks, risk-residual-
    panel), S6 ties value-only online but both are far below iSVD/hybrid.
    This is the FAM-02 regime (row-concentration guard), not the FAM-01
    regime.

Implication for FAM-01 (Stiefel rank-r lift) acceptance: the "close
≥50% of S6→online gap" target is now tractable on the matrices where
the gap is real. On etf-basket-basis the gap (cos1² 0.807 → 0.969)
needs 0.08 cos1² closure, which is the kind of lift a rank-r escape
from the P4 plateau could produce. On mixed-tail-balanced the
"surviving" gap (0.04) is within noise of a single bench run.

6. Reproducibility
-------------------

  Code change:    half_window_sliding_hmean_experiment.py:31-33,512-514
                  (pool split into VALUE_ONLY / ORACLE_AWARE; default
                  flipped to VALUE_ONLY; --online-include-oracle CLI
                  flag exposes the prior behavior).

  Bench command (per matrix M, this folder):
    python half_window_sliding_hmean_experiment.py \
      --matrix "$M" \
      --policies isvd combined hybrid future_hmean_online \
                 future_hmean_r_sk_g \
      --rsk-variant S6 \
      --half-win 32 \
      --json-out summary/bench_matrix_sweep_value_only_online/${M}_win64.json \
      --csv-out  summary/bench_matrix_sweep_value_only_online/${M}_win64.csv \
      --text-out summary/bench_matrix_sweep_value_only_online/${M}_win64.txt

  Files in this folder:
    {matrix}_win64.{json,csv,txt,log}   per-matrix bench output (all 8)
    synthesis.txt                       this file

  Total bench wall-clock: ~14 minutes (4-way parallel batches of ~3.5 min).

  To restore the oracle-aware behavior for any single run:
    add --online-include-oracle to the CLI.
