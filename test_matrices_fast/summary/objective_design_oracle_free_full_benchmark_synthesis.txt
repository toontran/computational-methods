Debug corrections
-----------------
1. Future-objective denominators

The first all-matrix run reported future-objective wins over 32 blocks even
though the final block has no future rows. The corrected benchmark now reports:

  valid_decisions

Future objectives have 31 valid decisions per 32-block matrix at horizon H=2,
because partial lookahead is allowed for block 31 and no lookahead exists for
block 32.

2. q2 is not the only success label

The original four stress matrices made q2_vs_q1oracle a good success proxy.
That is not true for all finance-themed matrices. In several families,
block_svd_complement or prev_opt2 can win while still having high oracle mass.

The corrected benchmark therefore reports:

  oracle90_win_count = winner has oracle_mass >= 0.90
  oracle99_win_count = winner has oracle_mass >= 0.99
  mean_winner_oracle_mass

q2 wins remain useful, but oracle-mass metrics are the better all-matrix
success criteria.

3. Zero-denominator ratios

Hard complement penalties intentionally assign zero score to the exact
block_svd_complement candidate. The old q2/block_svd ratio then became huge and
uninformative. The corrected benchmark keeps the ratio only when the denominator
is non-negligible and adds:

  mean_q2_margin_block_svd
  mean_q2_margin_opt2

4. Hard complement penalty can be too blunt

The original hard penalty:

  (1 - |v^T c_t|^2)

is good when the current-block SVD complement is a local-only artifact. It is
too blunt when the block-SVD direction is itself oracle-like. The corrected
benchmark adds adaptive penalties that reduce the penalty when a block-SVD-
aligned direction is also supported by full score, old rows, or future rows.


Notation
--------
For block t and candidate unit vector v:

  A_t       = current raw block
  M_t       = [carried sketch rows; A_t]
  C_t       = candidate set for the block
  c_t       = block_svd_complement, the top current-block right singular
              direction orthogonal to selected v1

Combined-score components:

  S_b(v) = block-only combined score
         = combined_score_component_details(A_t, A_t, v, ...)

  S_f(v) = full sketch-inclusive combined score
         = combined_score_component_details(M_t, A_t, v, ...)

Fresh/current gain:

  g_b(v) = ||A_t v||^2

Old-row reservoir support:

  old(v) = ||old_row_memory v||^2

Held-out future support, used only as an offline diagnostic:

  future(v) = sum over next H row blocks ||A_future v||^2

Response shape:

  relH(v) = entropy of current response energy (A_t v)^2 / log(block_rows)
  top4(v) = fraction of current response energy in the largest four rows

Complement alignment:

  a(v) = |v^T c_t|^2

Candidate-set shares:

  X_share(v) = X(v) / max_{u in C_t} X(u)

Harmonic mean:

  HM(x, y) = 2xy / (x + y + eps)


Objective derivations
---------------------
1. Corrected block-only score baseline

  J_block(v) = S_b_share(v)

Why:

  This is the corrected block-only score: fresh gain times pooled entropy. It
  is the baseline for checking whether block-only scoring is enough.

Expected failure:

  It often chooses block_svd_complement, because current-block gain is exactly
  what block_svd is optimized to maximize.

2. Entropy / anti-spike block score

  J_antispike(v) = S_b_share(v) * relH(v)

Why:

  Good repeated support should be spread across multiple rows, not dominated by
  one shock row.

Expected failure:

  A non-oracle block-SVD direction can still have diffuse row response, so
  entropy alone does not reject every complement.

3. Concentration-guarded block score

  J_conc(v) = S_b_share(v) * relH(v) * (1 - top4(v))

Why:

  relH can be insensitive to the largest few rows. The top-4 guard explicitly
  penalizes concentrated row support.

Expected failure:

  Same as entropy: diffuse but non-oracle block-SVD complements survive.

4. Full-vs-block combined score balance

  J_full_block(v) = HM(S_b_share(v), S_f_share(v)) * relH(v)

Why:

  A useful direction should be supported by fresh rows and should not disappear
  under the sketch-inclusive combined score.

Expected failure:

  S_f contains carried sketch state. It can preserve stale or misleading
  support, and it does not always reject block-SVD complements.

5. Old-row reservoir consistency

  J_old(v) = HM(g_b_share(v), old_share(v)) * relH(v)

Why:

  This is an online-style proxy for "support repeats outside the current
  block." It uses sampled raw old rows instead of the carried sketch rows.

Expected failure:

  The reservoir can be noisy or stale. It can prefer opt2 or mgain SVD
  complements and is not a reliable standalone oracle proxy.

6. Hard complement penalty

  J_comp(v) = S_b_share(v) * relH(v) * (1 - a(v))

Why:

  The repeated-support diagnostic showed that raw block gain is frequently
  dominated by the current block's SVD complement. This objective keeps fresh
  support but explicitly rejects current-block local complements.

Expected failure:

  If c_t itself is oracle-like, hard rejection may remove a valid direction.
  This matters in several finance-themed matrices where block_svd winners can
  have high oracle mass.

7. Old reservoir plus hard complement penalty

  J_old_comp(v) = HM(g_b_share(v), old_share(v)) * relH(v) * (1 - a(v))

Why:

  Combines recurrence in old raw rows with explicit block-SVD rejection.

Expected failure:

  It inherits the old-row reservoir instability.

8. Future consistency

  J_future(v) = HM(g_b_share(v), future_share(v)) * relH(v)

Why:

  This is the cleanest offline oracle-free proxy for repeated support: a
  direction should be good on the current block and on independent future rows.

Expected failure:

  It is not online deployable as written and can still choose block_svd when
  the block-SVD direction generalizes.

9. Future consistency plus hard complement penalty

  J_future_comp(v) =
      HM(g_b_share(v), future_share(v)) * relH(v) * (1 - a(v))

Why:

  Offline diagnostic for support that is fresh, future-consistent, diffuse,
  and not just the current block's SVD complement.

Expected failure:

  Same hard-penalty caveat: valid block-SVD-aligned directions are suppressed.

10. Adaptive full complement penalty

  J_adapt_full(v) =
      S_b_share(v) * relH(v) * (1 - a(v) * (1 - S_f_share(v)))

Why:

  Penalize block-SVD alignment only when the direction lacks full-score support.
  If a block-SVD-like direction is also strong under S_f, do not zero it out.

Expected failure:

  S_f can be contaminated by carried sketch state. On residual-spiky-shocks,
  this adaptive full penalty lets too many block_svd directions back in.

11. Adaptive old complement penalty

  J_adapt_old(v) =
      S_b_share(v) * relH(v) * (1 - a(v) * (1 - old_share(v)))

Why:

  Penalize block-SVD alignment only when it lacks old-row reservoir support.

Expected failure:

  It can inherit stale/noisy reservoir behavior and may allow block_svd back in
  finance-style matrices.

12. Adaptive future complement penalty

  J_adapt_future(v) =
      HM(g_b_share(v), future_share(v)) * relH(v)
      * (1 - a(v) * (1 - future_share(v)))

Why:

  Offline version of adaptive complement rejection: a block-SVD-aligned
  direction is allowed if it generalizes to future rows.

Expected failure:

  It is not online deployable as written, and it can allow some block_svd wins
  when those directions have future support.

Interpretation
--------------
1. Raw block score is not defensible as the objective.

Across all matrices:

  obj_block_score: block_svd 400/576, mean oracle_mass 0.712310

This reproduces the corrected block-only lesson at larger scale.

2. Entropy and concentration guards are useful but incomplete.

They greatly improve the stress group but still leave many block_svd wins:

  obj_block_antispike:           block_svd 303/576
  obj_block_concentration_guard: block_svd 236/576

This confirms that a non-oracle complement can have diffuse row response.

3. Full/block harmonic mean is useful but not enough.

  obj_full_block_hmean:
    q2 273/576
    block_svd 62/576
    opt2 143/576
    mean oracle_mass 0.872722

It reduces block_svd but replaces some failures with opt2/stale-score wins.

4. Old-row reservoir alone is unstable.

  obj_old_block_hmean:
    mean oracle_mass 0.803160
    opt2 164/576

Old raw rows are a useful signal, but not a standalone proxy for oracle
consistency.

5. Hard complement penalty is the best online-style conservative objective.

  obj_complement_penalty:
    q2 315/576
    block_svd 0/576
    opt2 38/576
    oracle90 533/576
    oracle99 477/576
    mean oracle_mass 0.941645

This is the best objective if the design goal is to suppress local block-SVD
chasing aggressively without using future rows.

6. Future + hard complement is the best conservative offline diagnostic.

  obj_future_complement_penalty:
    q2 313/558
    block_svd 0/558
    opt2 22/558
    oracle90 523/558
    oracle99 468/558
    mean oracle_mass 0.950191

This remains the best offline target when block_svd must be rejected.

7. Adaptive future complement has the best mean oracle mass, but is less
   conservative.

  obj_adaptive_future_complement:
    q2 326/558
    block_svd 38/558
    opt2 83/558
    oracle90 517/558
    oracle99 460/558
    mean oracle_mass 0.957845

It allows block_svd-aligned candidates when future rows support them. That is
exactly the intended correction for finance-style matrices where block_svd can
be oracle-like. The cost is that it no longer enforces zero block_svd wins.


Recommended objective stack
---------------------------
For an online objective experiment, use the hard complement objective first:

  J_online(v) = S_b_share(v) * relH(v) * (1 - |v^T c_t|^2)

Why:

  - best online conservative all-matrix result;
  - zero block_svd wins by construction;
  - high oracle90/oracle99 rates;
  - strong on the original stress matrices.

For a less conservative online variant, test:

  J_adapt_old(v) =
      S_b_share(v) * relH(v)
      * (1 - |v^T c_t|^2 * (1 - old_share(v)))

Why:

  - keeps the complement penalty;
  - allows SVD-complement-aligned directions if old raw rows also support them;
  - performs well on stress, but permits more block_svd wins in finance.

For offline validation, use both:

  J_future_comp(v) =
      HM(g_b_share(v), future_share(v)) * relH(v) * (1 - |v^T c_t|^2)

and:

  J_adapt_future(v) =
      HM(g_b_share(v), future_share(v)) * relH(v)
      * (1 - |v^T c_t|^2 * (1 - future_share(v)))

Why both:

  - J_future_comp measures conservative non-complement future consistency;
  - J_adapt_future measures whether block-SVD-aligned support actually
    generalizes and should not be automatically rejected.


Updated takeaway
----------------
The corrected all-matrix benchmark changes the earlier conclusion slightly.

Earlier:

  block_svd_complement is the bad fresh-row challenger.

Corrected:

  block_svd_complement is bad when it is local-only. In several finance-themed
  matrices it can be oracle-like, so the benchmark must distinguish local-only
  complement chasing from complement-aligned support that repeats across other
  evidence channels.

The most robust objective family is therefore:

  fresh block score
  x row-response entropy / anti-spike guard
  x complement-locality control

where complement-locality control can be:

  hard:     reject |v^T c_t|^2 directly;
  adaptive: reject |v^T c_t|^2 only when full/old/future support is weak.

The hard version is the best conservative online candidate. The adaptive
future version is the best offline oracle-free diagnostic by mean oracle mass.
