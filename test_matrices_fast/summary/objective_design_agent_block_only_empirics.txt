Block-only oracle-vs-fake recheck
=================================

Date: 2026-04-22

Scope
-----
I reran the second-slot comparison with the updated rule:

  - gain / energy uses `A_block` only
  - entropy still pools the current block with `old_row_memory`

I used an inline Python harness over `probe.entropy_iter_basis_forget` and
`probe.combined_score_component_details`, with `old_row_memory` selected from
the seen rows at each step.

Run settings
------------
  - `n=256`, `win=32`, `rank=2`
  - `old_memory_size=32`
  - `preset="fast"`
  - `dtype=float32`
  - matrices: `static-cex`, `diffuse-diffuse`, `mixed-tail-sharp`,
    `residual-spiky-shocks`
  - row shuffling: off for `static-cex`, on for the other three

Commands run
------------
  python3 - <<'PY' ... inline block-only comparison harness ...

Interpretation
--------------
1. The prior "oracle-like second slot wins gain immediately" conclusion does
   not survive this stricter scoring rule. On these reruns, `q2_vs_q1oracle`
   and `q2_vs_v1opt` rarely beat `opt2` on score, and their gain wins are only
   occasional.

2. `svd_complement` is the main block-only gain challenger. It wins the gain
   comparison most often on every matrix, and dominates best-gain counts on the
   first three matrices.

3. Entropy patterns still matter, but they are no longer enough to flip the
   outcome. `q2_vs_q1oracle` usually has higher pooled relative entropy than
   `opt2`, yet `opt2` keeps the better block-only score.

4. `prev_opt2` remains a weak comparator on both score and gain.

Bottom line
-----------
Under block-only gain with pooled current-block+memory entropy, the main
change is that the oracle-like second-slot candidates are less competitive than
before. The strongest gain competitor is now `svd_complement`, while `opt2`
still usually wins the score comparison.
