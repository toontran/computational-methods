Current promoted method
-----------------------
Use the combined score variant with greedy rank-by-rank selection and
row-normalized SVD initialization on every block.

Current deployable settings:

  score_variant: combined
  basis_selection: greedy
  joint_warm_start_oracle: False
  oracle_candidate_check: False
  rownorm_seed_all_blocks: True
  row_concentration_lambda: 0
  old_memory_size: win

For n=128, win=32 this means:

  current block rows: 32
  retained old rows: up to 32
  entropy rows after warmup: up to 64

The retained old-row memory is selected from rows seen so far using half
uniform rows and half high-response rows under the current carried subspace.

Decision log
------------
Promoted:

  combined + greedy + rownorm_seed_all_blocks + old_memory_size=win

Reason:

  This is deployable, uses no oracle information, preserves the combined
  objective, and improves/static-stabilizes static-CEX relative to iSVD and FD
  under the shuffled small benchmark.

Refined:

  old_memory_size changed from 64 to win.

Reason:

  With win=32, old_memory_size=64 used 32 current rows plus 64 retained old rows
  in the entropy term after warmup. The current refinement uses a symmetric
  current/old row budget of 32 + 32. Static-CEX top-1 metric improved slightly
  under explicit shuffle:

    old_memory_size=64: align 0.979077, relerr 0.00034025
    old_memory_size=32: align 0.981618, relerr 0.00033069

Rejected for default:

  row_concentration_lambda=0.1

Reason:

  Under global row shuffling and rownorm seeding on all blocks, lambda=0.1 gave
  only tiny wins on a few easy cases and materially worsened risk-residual-panel:

    lambda=0:   risk-residual-panel align 0.280023, relerr 0.01205599
    lambda=0.1: risk-residual-panel align 0.338375, relerr 0.01674531

Rejected for this benchmark path:

  joint optimization after greedy

Reason:

  It can chase a higher combined objective that does not reliably improve the
  target alignment. The current benchmark path is intentionally plain greedy.

Rejected for deployable comparisons:

  oracle warm starts and oracle candidate replacement

Reason:

  They use V_exact and are diagnostic only.

Current interpretation
----------------------
Static-CEX:

  Combined is clearly better than iSVD and FD on both top-1 alignment and
  singular-value error under the small shuffled benchmark. However, static-CEX
  should also be reported with a rank-2 subspace metric because the current
  mean_align is top-1 only and can understate the quality of a correct rank-2
  subspace when the leading pair rotates.

FD:

  FD often has competitive top-1 alignment on some easy/smooth cases, but its
  singular-value shrinkage is too large for this benchmark family.

iSVD:

  The easy/smooth cases mostly saturate the top-1 projection metric near 1, so
  tiny ordering differences should not be overread. Combined remains
  competitive and has the clear top-1 alignment win on static-cex, while FD's
  singular-value shrinkage remains the main baseline failure mode.


Known metric issue
------------------
Current benchmark output reports:

  mean_align = ||V_r V_r^T V_exact[:, :1]||_F

This is a top-1 metric. For rank=2 near-tie cases, especially static-CEX, it
can be misleading because the selected rank-2 subspace can be nearly correct
while the compressed first vector rotates within that subspace.

Add a rank-r subspace metric before drawing strong conclusions on larger
static-CEX-like matrices:

  rank_r_subspace_align = ||V_r[:, :r] V_r[:, :r]^T V_exact[:, :r]||_F / sqrt(r)

Keep the old top-1 metric as a secondary diagnostic.
