Consecutive tail-conspiracy diagnostic
=====================================

Date: 2026-04-21

Question
--------
Test whether the combined-score failures are caused by:

  A. the same wrong tail direction/subspace persisting consecutively;
  B. fresh tail mixtures being re-fit to each sampled pooled row set; or
  C. the row-memory sampling mechanism already preventing the effect.

The key objection tested here is that combined entropy is computed on raw old
row memory plus the new window, not on sketch rows. Therefore, if the failure
were only a sketch-entropy artifact, an independent old-row holdout should knock
down the selected optimizer directions.


Implementation
--------------
Added a diagnostic flag to `cex_restricted_space_probe.py`:

  --dump-consecutive-tail-diagnostics

It prints, per block:

  - principal cosines between current selected frame and previous selected frame;
  - principal cosines between current selected frame and the projected QR oracle;
  - signal mass and tail mass relative to V_exact[:, :rank];
  - current optimizer score/entropy on the training old row memory used by the
    objective;
  - projected QR oracle score/entropy on the same training memory;
  - previous selected frame scored under the current objective;
  - current optimizer and QR oracle score/entropy on an independent old-row
    holdout sampled from old raw rows excluding the training memory indices.

The holdout is unavailable in block 2 for win=32, old_memory_size=32 because all
previous raw rows are already in the training memory. Blocks 3 onward have an
excluded-row holdout.

Raw outputs:

  summary/mixed_tail_sharp_consecutive_diag_raw.txt
  summary/diffuse_diffuse_consecutive_diag_raw.txt
  summary/static_cex_consecutive_diag_raw.txt


Command Template
----------------
All three runs used:

  python cex_restricted_space_probe.py \
    --matrix MATRIX --n 1024 --win 32 --rank 2 \
    --preset fast --seed 0 \
    --shuffle-rows --row-shuffle-seed 0 \
    --mode restricted --score-variant combined \
    --basis-selection greedy --reduced-optimizer cex \
    --rownorm-seed-first-block --rownorm-seed-all-blocks \
    --q0 8 --qmax 48 --num-restarts 8 --maxit 120 \
    --expansion-maxit 8 --post-expansion-maxit 80 \
    --expansion-direction residual \
    --reuse-line-search-grad --expansion-warm-start \
    --dtype float32 --old-memory-size 32 \
    --oracle-candidate-check \
    --dump-consecutive-tail-diagnostics

Definitions:

  prev_cos_min:
    min principal cosine between selected frames in consecutive blocks.

  tail_prev_min:
    min principal cosine between the tail components of consecutive selected
    frames after removing V_exact[:, :rank].

  oracle_cos_min:
    min principal cosine between current selected frame and projected QR oracle.

  tail_mass:
    ||(I - P_exact) V_opt||_F^2 / rank.

  train_relH and hold_relH:
    average pooled relative entropy across the two selected directions on the
    training row memory and excluded-row holdout, respectively.

  hold_score_gap:
    holdout score_sum(V_opt) - holdout score_sum(Q_oracle).

Interpretation:

  The diagnostic does not simply flag every run as bad. Static-cex also has
  large consecutive selected-frame and tail-residual cosines, and it is
  tail-heavy early: block 3 has tail_mass = 0.942897 and block 12 still has
  tail_mass = 0.697517. Those quantities alone are therefore not diagnostic.
  The difference is temporal resolution. Static-cex moves from a transient
  tail-heavy state into the oracle span: by the final block, the selected frame
  and QR oracle are essentially the same rank-2 subspace, and the remaining tail
  mass is small. The small final score gap is negligible and both train and
  holdout agree.


Conclusion
----------
The row sampling mechanism fixes the earlier sketch-row entropy issue, but it
does not prevent consecutive tail conspiracy in the tested failures.

What the new diagnostic supports:

  1. The failure is not just overfitting to the particular old-row memory.
     On mixed-tail-sharp and diffuse-diffuse, optimizer directions retain high
     entropy and higher score on excluded old-row holdout.

  2. The same tail region can persist consecutively.
     Consecutive selected-frame overlap and tail-component overlap are high,
     especially after the first few blocks. This is stronger than "fresh,
     unrelated tail mixtures every block." However, static-cex shows that early
     high tail mass and high tail-residual persistence are not sufficient by
     themselves; the failure signature is persistence without later convergence
     to the oracle span.

  3. It is not necessarily the same exact tail vector forever.
     Some blocks still show drift or one direction swapping/rotating, especially
     in mixed-tail-sharp. The robust statement is persistence of a wrong tail
     subspace/family, with enough continuity for the carried sketch to reinforce
     it.

  4. The static-cex control behaves differently.
     The same diagnostic shows convergence to the oracle span, so the test is
     distinguishing real bad cases from the known success case.

Practical implication:

  A single raw-row reservoir is not enough as a guardrail. If the tail subspace
  is broad enough, selected tail mixtures can pass both the training row memory
  and an excluded-row holdout. The next fix should not only add row-sample
  validation; it should add a second discriminator such as stronger SVD/FD
  gating, larger candidate retention with SVD compression, or persistence
  checks against independent row partitions and not only against the carried
  sketch.
