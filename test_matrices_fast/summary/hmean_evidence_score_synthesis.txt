HM-evidence score: multi-matrix benchmark synthesis
====================================================

Date: 2026-04-27


Setup
-----
Streaming run with score_variant="combined" advancing the carried state
(diag(s)·V.T) across blocks. At each reported block we compare four
candidates plus the projected oracles on the new HM-evidence score.

Generation params (matched across all matrices):
  n=1024, half_win=32, rank=2, seed=0,
  shuffle_rows=True, row_shuffle_seed=0, dtype=float32,
  r_sig=2, alpha_sig=0.003, alpha_tail=0.0145, tail_scale=0.99,
  sigma1=0.991, v_type=rand.

Score (full definition in
  summary/hmean_evidence_score_instructions.txt §2):

  raw_sk(v) = ||A_sketch v||^2,  raw_g1(v) = ||A_cur v||^2,
  raw_g2(v) = ||A_fut   v||^2

  c_sk = sk_end / ||A_sk_full||_F^2
  c_g1 = N_block / ||A_cur||_F^2
  c_g2 = N_block / ||A_fut||_F^2

  u_k(v)   = c_k · raw_k(v)              # rows of mean-row energy
  HM_evi(v)= W / (w_sk/u_sk + w_g1/u_g1 + w_g2/u_g2),
             W = w_sk + w_g1 + w_g2,
             w_sk = r = 2,  w_g1 = w_g2 = N_block = 32

  score(v) = HM_evi(v) · relH1(v)        # relH1 = entropy(A_cur v) / log(N_block)

Block 1 path drops the sketch term entirely (W → w_g1 + w_g2).

Optimizer: shared `optimize_future_hmean_in_basis` from
`future_hmean_optimizer_diagnostic.py`, monkey-patched with
`hm_evi_value_grad`. Search basis B_search includes A_sketch ∪ A_cur ∪ A_fut
(orthogonalized against V_default[:,0]). 24 random restarts; oracle_v1_proj
and oracle_v2_proj added as warm starts.

Gradient verification: max relative error 4.4e-10 (block 12), 2.1e-10 (b6),
1.4e-10 (b2). Centered differences h=1e-6, 20 sampled coords, float64.

etf-basket-basis post-mortem
----------------------------
oracle_v1_proj has align_v1 ≈ 0.999 across all blocks — it is essentially
V_exact[:,0]. On this matrix the carried state and combined-greedy slot 0
already lock onto V_exact[:,0], so V_default[:,0] ≈ oracle_v1_proj.

The HM-evidence optimizer searches the orthogonal complement of
V_default[:,0] (matching the existing slot-2 protocol from
`future_hmean_optimizer_diagnostic.py`). Once V_default[:,0] is removed,
oracle_v1_proj's residual component in B_search is tiny: any warm start
near oracle_v1_proj is normalized to a vector orthogonal to V_default[:,0],
so the optimizer cannot reach the strong-signal direction.

oracle_v2_proj does NOT have this issue (it's orthogonal to V_default[:,0]
by construction on this matrix). evi_best beats oracle_v2_proj at every
block on etf-basket-basis (3.57 vs 3.19 b2; 3.79 vs 1.64 b6; 3.90 vs 0.83
b12). So the score function is sound — the comparison vs oracle_v1_proj
is structurally one-sided, not a defect of the new score.

Take-away: when the slot-0 pick already captures the dominant signal,
the slot-2 optimum is necessarily not the strongest signal direction.
Comparing to oracle_v1_proj in this regime measures "how much could the
unconstrained search recover", which is not what the slot-2 objective
optimizes.

evi_best's combined_score is consistently 30–53% of combined_v2's. This
is the intended trade: evidence-balanced ≠ combined-optimal. The new
score deliberately constrains all three of (sketch evidence, current,
future) to be balanced; that costs combined_score because combined
collapses gain2 to 0.

Summary
-------
The HM-evidence score replaces pool-normalized denominators with per-block
mean-row energies and weights the carried sketch by its rank rather than
the cumulative row count. On the eight-matrix bench this yields:

  - evi_best dominates norm-HM, raw-HM, and combined_v2 on the new score
    by 1–2 orders of magnitude at every block on every matrix.
  - evi_best matches or beats both projected oracles on 7/8 matrices.
    The single exception (etf-basket-basis vs oracle_v1_proj) is a
    structural artifact of the slot-2 search basis excluding V_default[:,0],
    not a score defect.
  - evi_best concedes ~50% of combined_score relative to combined_v2,
    consistent with the framing that the score is a different objective,
    not a tighter combined surrogate.
  - Gradient correctness verified to 1e-10 relative error.


Notes on what was changed
-------------------------
hmean_evidence_score.py builds B_search from rowspace(A_sketch ∪ A_cur ∪
A_fut), not just A_cur ∪ A_fut. The latter (which the existing diagnostics
use because their objectives don't reference A_sketch) excluded the rank-r
sketch directions from the search and prevented the optimizer from
reaching oracle_v?_proj on matrices where the oracle has support outside
A_cur ∪ A_fut. Including A_sketch in B_search lifted score(evi_best)
above score(oracle_v?_proj) on diffuse-diffuse, mixed-tail-soft, and
restored a strict win on mixed-tail-balanced block 6.

`future_hmean_optimizer_diagnostic.py`, `hmean_combinations_optimizer_diagnostic.py`,
and the streaming carry rule were not touched, per §7 of the instructions.


Open questions (carried over from instructions §8)
-------------------------------------------------
  - Whether w_sk should soft-gate by the cross-block agreement
    ||V_carried^T V_local||_F^2 / r. Untouched here.
  - Whether relH1 should be redefined over A_sketch ∪ A_cur (would
    change the gradient). Untouched here.
  - Whether to switch to a Stiefel rank-2 optimization when evi_best
    is consistently nearly collinear with V_default[:,0]. The slot-2
    sphere search was sufficient on every matrix in this suite.
