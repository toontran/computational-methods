Testing a new HM-type slot-2 score: context + instructions
==========================================================

Date: 2026-04-27
Audience: someone proposing a new variant in the `r_sk_g_score.py` family
(or a structurally different rank-2 / Stiefel score) and running the same
diagnostic + benchmark gauntlet used for S1–S5.


0. TL;DR
--------
- Add the new variant to `r_sk_g_value_grad` (`r_sk_g_score.py:67`) as a
  new `variant` branch returning (score, grad, r_sk, raw_g1, raw_g2, hm_g,
  sat_term, s_align). Block-1 fall-through must be defined (no sketch yet).
- Wire it into the per-block diagnostic by extending the for-loop on
  variants and adding optimizer + v1_full / v2_deflate candidates if the
  variant is different enough to warrant separate optimizer state.
- Add the variant string to `--rsk-variant` choices in
  `half_window_sliding_hmean_experiment.py:899`.
- Run T1 (FD), T2 (per-block table on 4 blocks × 3 matrices), T3 (streaming
  bench on 3 matrices, optionally 17). Acceptance criteria below.
- Inspect the diagnostic-vs-streaming gap: a variant that lifts T2 might
  still be a no-op in T3 if its preferred direction lies in span(V_default[:, 0]).

6. Pitfalls (each one cost a non-trivial debugging cycle)
---------------------------------------------------------

P1. Random v on the sphere is below the gate.
    For any score that gates on raw_sk > T (or any function of
    ‖B_top v‖²), a unit-sphere random v has expected raw_sk ≈
    ‖B_top‖²_F / n, which is well below T = ‖A_seen‖²_F / N_seen for
    small ranks. FD trivially passes (0 vs 0). Probe at the carry
    direction state.V[:, 0] for FD validation.

P2. Slot-1 deflation kills carry-aligned candidates in streaming.
    The streaming wiring runs slot-2 over `B_search = B_union ⊥
    V_default[:, 0]`. If your variant prefers a direction in
    span(V_default[:, 0]) (e.g. sketch_v[:, 0] for S5), that direction
    is unreachable in streaming. The per-block diagnostic uses
    `B_union` (no deflation), which is why diagnostic gains may not
    transfer. To exploit a carry-aligned variant: drop the deflation
    and let the score pick BOTH slots, or use the variant's slot-1
    pick as the new V_default[:, 0].

P3. `future_hmean_online` includes an oracle-aware candidate.
    `ONLINE_POOL` includes `q2_vs_q1oracle = V_exact[:, 1] projected
    onto rowspan(M_gain), QR-orthogonalised vs V_exact[:, 0]_proj`.
    Selected ~4 of 31 blocks on static-cex sliding. So online vs S*
    is not a fair streaming comparison. The fair baseline for a
    streaming-only variant is `combined`; online's edge over
    combined is partly the oracle peek. To get a clean comparison,
    either drop `q2_vs_q1oracle` from `ONLINE_POOL` (line 24) or
    explicitly note the oracle dependence.

P4. Scalar-per-v plateau. Any function of (raw_sk, g1, g2) has a
    62-dim level set in R^64 union. On counterexample matrices, the
    plateau value is ≈ 0.52 (HM3 max under raw_g1=raw_g2=0.42,
    r_sk=1) and the oracle is NOT at that plateau (its raw_sk and
    raw_g values are different). No reweighting of (raw_sk, g1, g2)
    can fix this — the oracle is a single direction, the plateau is
    a manifold. Stiefel rank-2 (V is n×2 frame, score uses
    ‖A_fut V‖²_F not ‖A_fut v‖²) is the documented escape.

P5. The streaming bench `final_*` numbers are at block 31. For
    intermediate-block analysis, use the `rows` field in the JSON
    (per-block trajectory) — block 1 is at the noise floor for every
    policy, block ~28+ is where the carry stabilises.

P6. Per-block constants (c_sk, c_g1, c_g2) must be recomputed in two
    places that are easy to miss:
      (a) `per_block_constants` in hmean_evidence_score.py
      (b) inline in `half_window_sliding_hmean_experiment.py:578-583`
    Keep them consistent — `c_sk = N_sk / ‖A_seen‖²_F` (typical-row
    energy formula).


7. Open design directions
-------------------------

D1. Stiefel rank-2 score (the §9 escape).
    score(V) = HM3(r_sk_F(V), ‖A_cur V‖²_F, ‖A_fut V‖²_F) · relH1
    where r_sk_F(V) is some Frobenius-level shortfall/excess on
    ‖B_top V‖²_F. Optimization: project gradient onto the Stiefel
    manifold (Cayley retraction or QR). Candidate frames:
    V_default[:, :2], oracle V_exact[:, :2]_proj, sketch_v[:, :2].
    Replace align_v[12]_proj with principal-angle² between candidate
    frame and span(oracle_v[12]_proj).

D2. Drop slot-1 deflation in streaming.
    Let the new score pick BOTH v1 and v2 in B_union, then use rank-2
    SVD reframe over span{v1, v2}. Slot-1 will no longer be locked to
    combined's V_default[:, 0], so the new variant's preferred
    carry-aligned basin is reachable.

D3. Continuous gate.
    Replace the hard clip `score = 0 if raw_sk < T` with a soft weight
    w(raw_sk; T) — e.g. sigmoid((raw_sk - T) / scale) — to provide
    gradient signal in the clipped region. Trade-off: re-introduces
    some plateau but gives the optimizer something to climb.

D4. Multi-block lookahead.
    Replace A_fut (single half-window) with vstack of multiple future
    half-windows. Reduces the row-of-A_fut cheat (one row dominating
    A_fut) and matches the multi-block carry the streaming pipeline
    actually faces. Cost: more memory, more compute per block.

D5. LOO-style validation.
    Score v on (A_cur, A_fut) where each block's score uses the
    OTHER block as the "future". Removes the implicit dependence on
    the half-window split. Per-block diagnostic only — streaming
    cannot use future blocks it hasn't seen.
