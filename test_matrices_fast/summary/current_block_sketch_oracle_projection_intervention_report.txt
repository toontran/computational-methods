Current-block-plus-sketch oracle projection intervention report
===============================================================

Date: 2026-04-23

Purpose
-------
Check whether the failed b1/b2 interventions are failing because the oracle
direction is absent from the current [sketch; block] rowspace, or because the
optimizer/compression path is not selecting it even when it is present.


Code changes
------------
Updated:

  second_slot_tail_bias_diagnostic.py

The trajectory summary now prints, for every logged block:

  block_sketch_oracle_cos
    Principal cosines between the selected rank-2 frame and the QR frame of the
    true rank-2 oracle span after projecting that oracle span into the current
    M_gain = [carried sketch; current block] rowspace.

  exact_oracle_cos
    Principal cosines between the selected rank-2 frame and the original global
    oracle frame V_exact[:, :2].

  oracle_proj_norm
    Norms of each original oracle column after projection into the current
    [sketch; block] rowspace. These are per raw oracle column, not principal
    cosines. If one projected oracle column is weak, the QR projected-oracle
    frame can rotate, so interpret these alongside block_sketch_oracle_cos.

Compression variant notes
-------------------------
Final-block compression variants show that the oracle projected comparator is
always able to recover rank-2 when the oracle frame is injected:

  oracle_projected: variant_oracle2_projection = 1.0 and variant_subspace_cos2 = 1.0

But that is a diagnostic upper bound, not a deployable compression rule.

For mixed-tail-sharp:

  - internal_rank=8 contains oracle-2 internally with int_o2=0.997077 and
    int_cos2=0.996925, but left_projected/internal_projected_svd compress to
    comp_cos2=0.121553.
  - internal_rank=16 also contains oracle-2 internally, but comp_cos2 is only
    0.469343.
  - actualB score optimization inside the internal subspace selects essentially
    the same bad final frame as left_projected in these final-block checks.

For diffuse-diffuse:

  - rank 2 misses oracle-2 internally.
  - rank 4 and above put oracle-2 into the internal subspace.
  - rank 8 is the best final compressed subspace among this run, with comp_cos2
    0.938288, though the second column is rotated away from projected oracle-2.

For static-cex:

  - rank 2 and 4 work.
  - rank 8 and 16 show that oversampling alone can hurt if the final compression
    rule is not oracle-aware; oracle-2 is present internally but discarded by
    the default left_projected compression.


Interpretation
--------------
1. Mixed-tail-sharp is not just an early b1/b2 seeding problem.

   In several intervention modes, raw oracle-2 is present in [sketch; block] at
   the final block, but the selected second direction is not aligned with the
   projected oracle frame. The failure is therefore in selection/compression
   under the current objective and frame, not merely absence of oracle-2.

2. Diffuse-diffuse is mostly an early capture problem at rank 2.

   Normal rank-2 loses oracle-2 internally. Forcing b1/b1b2 or increasing
   internal rank can make oracle-2 present. However, internal rank 4/16 still
   show compression losses, so internal retention is necessary but not
   sufficient.

3. Internal oversampling answers a different question from b1/b2 replacement.

   Oversampling often proves oracle-2 can be retained internally. It does not
   automatically solve the final rank-2 handoff. The final compression rule can
   discard or rotate away from oracle-2 even when int_o2 is near 1.

4. The objective gap is real.

   In final-block compression variants, oracle_projected often has slightly
   lower actualB score than the bad selected frame, while the bad frame has
   higher actualB score. That is direct evidence that the current objective can
   prefer the wrong rank-2 frame even when the oracle frame is available.


Bottom line
-----------
Replacing b1/b2 does not help mixed-tail-sharp final alignment because the
system can still preserve or recreate a high-scoring non-oracle second slot
later. Checking the oracle projection onto current [sketch; block] confirms
that oracle-2 is often available at the final block but not selected.

Internal rank helps diagnose the mechanism:

  - rank-2 diffuse-diffuse misses oracle-2 internally;
  - rank-8 diffuse-diffuse can recover the final subspace;
  - mixed-tail-sharp can contain oracle-2 internally at rank 8/16 but still drop
    it during final compression;
  - static-cex shows oversampling can hurt if compression is not controlled.

The next useful experiment is not simply "larger internal rank"; it is larger
internal rank plus an oracle-free final compression criterion that preserves
directions with repeated old/future/block support instead of default
left-projected/SVD or actualB-score compression.
