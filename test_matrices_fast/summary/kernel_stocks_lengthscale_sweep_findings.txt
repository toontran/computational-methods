## Question

The port session (utils_combined_hybrid_port_session_notes.txt §4) concluded
that `entropyscore_hybrid` / `entropyscore_combined` only beat `isvd` when
σ₁/σ₂ is near-tied, and speculated that lowering the RBF lengthscale on
`kernel_stocks` would close the gap and move the matrix into that regime.
The parked experiment (§5) was left for a follow-up.

This session ran that experiment at N=1000.


## Headline finding

**Lowering the lengthscale closes σ₁/σ₂, but does NOT move kernel_stocks
into the regime where hybrid/combined uniformly beat iSVD.** The picture at
ls=0.02 is k-dependent and overall still favors iSVD, for two intertwined
reasons — summarized in §3 ("why") and §4 ("empirical table").

## 2. Structural lesson

On a real point cloud, RBF kernel lengthscale trades σ-gap *against*
row-entropy — cannot get both near the diffuse-diffuse corner:
  - Small ls → kernel ≈ identity → top singular vectors collapse on
    ~3–5 rows (r80 → 3.5) → row-entropy collapses → concentrated U.
  - Large ls → U diffuse (r80 → 187) → spectrum spreads → σ-gap grows.

Diffuse-diffuse achieves close-σ via Hadamard-seeded U (all rows ~1/√n),
*independent* of spectrum. RBF on a spatial point cloud cannot replicate
that geometry.


## 3. Score-component diagnostic (diag_hybrid_stocks_ls002.py)

Simulated single greedy-step, N=1000, ls=0.02, 10 prior blocks × 10 rows
as streaming history, rows_ref = N = 1000, evaluated on current block of
10 rows.

                            phi range        gain^2 range
  oracle (top-5 of full K)  [1.00, 1.05]     [0.00, 0.06]
  iSVD pick (current block) [1.00, 1.16]     [1.01, 2.39]
  iSVD pick (all seen)      [1.00, 1.18]     [0.00, 2.24]
  random orthonormal        [2.27, 2.48]     [0.006, 0.016]

**φ's dynamic range ~2.5×** across candidate directions, while **gain²'s
dynamic range is ~400×** per block. Head-to-head ranking of {oracle /
iSVD / random} column-0 vectors is identical by gain² and by combined
score on this matrix → φ cannot reorder top candidates. This predicts
combined-score ≈ gain² → equivalent to iSVD.

Reality (§4) is more nuanced because the actual sweep runs a multi-block
greedy with warm-start, not a single-shot scoring of pre-selected
candidates. What §3 shows: the *scoring signal* on kernel_stocks does not
point in a different direction from gain² alone. Any hybrid-vs-iSVD
divergence in §4 comes from optimizer trajectory differences, not
from the combined score steering toward a different goal.

Patterns:
  a) Small k (≤ 6): iSVD wins every i-slot. Top rows of the near-diagonal

     wins i=2..3. Hybrid captures the single strongest direction and
     the "tail" direction well, but misses the mid-band.

## 5. Takeaway

For a real-kernel matrix like kernel_stocks, lengthscale tuning can
narrow σ₁/σ₂ but cannot provide the row-diffuse geometry combined-score
was designed to exploit. On this matrix hybrid ≤ iSVD in most
(k, i) slots; the only regime where hybrid shows promise is mid-k on
*specific* directions (i=1 and the tail), not uniformly.

To exercise the hybrid-wins regime on "real" data, prefer matrices where
close-σ does NOT imply near-identity:
  - Graph Laplacians on expander / pseudo-random graphs
  - Well-mixed Markov chain transition matrices at small spectral gap
  - Kernels on (near-)uniform-on-sphere points rather than clustered
    financial data
  - Synthetic diffuse-diffuse (already in
    cex_restricted_space_probe.py:3085 generate_diffuse_diffuse_input)


## 6. How to replicate

### 6a. Prerequisites

  - Python with numpy, scipy, and the project utils on path
  - ~/data/data_2m.mtx  (stocks point cloud, 2-D)
  - systemd user scope available (for CPU throttling in the sweep)

### 6b. Files in this session (in /home/ttran02/pj/computational-methods)

  run_sweep.sh                                     # main driver (20 machines)
  diag_hybrid_stocks_ls002.py                      # score-component diagnostic
  test_matrices_fast/compare_hybrid_isvd.py        # post-hoc comparison
                                                   # (also kept at /tmp/compare_hybrid_isvd.py)

### 6c. Config changes applied

  run_sweep.sh:
    method_name="${METHOD_NAME:-entropyscore_hybrid}"   # env-overridable
    matrix_name="kernel_stocks_${N}_0.02"               # tightest σ-gap
    FORGET_ARGS: --num-restarts 8                       # (was 2, bumped
      per utils_combined_hybrid_port_session_notes.txt §3: --num-restarts 2
      is nondeterministic at close-σ due to float32/BLAS path divergence)
    N=1000

### 6d. Sweep launch

  chmod +x run_sweep.sh  # once, if needed

  mkdir -p logs/sweep_driver
  for m in $(seq 0 19); do
    nohup env METHOD_NAME=entropyscore_hybrid OUTPUT_NAME=output \
      bash run_sweep.sh $m > logs/sweep_driver/hybrid_m${m}.log 2>&1 &
  done
  for m in $(seq 0 19); do
    nohup env METHOD_NAME=isvd OUTPUT_NAME=output \
      bash run_sweep.sh $m > logs/sweep_driver/isvd_m${m}.log 2>&1 &
  done
  disown -a

Notes:
  - 40 concurrent workers. CPUQuota=50% of nproc per scope (8 cores on a
    16-core box). Heavy CPU contention but OK on a 125GB-RAM node.
  - Each main.py invocation runs 5 row-permutations internally.
  - Per-machine grid: 8 distinct (k, win, sr) configs after dedup. Total
    work per method = 20 machines × ~8 configs × 5 perms = 800 runs.
  - For N=1000, iSVD runs finish in minutes; hybrid greedy runs take
    hours at large k (k=206+ can be >24h per permutation).

### 6f. Comparison script

The comparator test_matrices_fast/compare_hybrid_isvd.py reads
canonical_angles_data_*.txt from every completed output folder, computes
`align_i` per block, and averages over blocks then row-perms. Point it
at a different matrix prefix by editing the regex `PAT`.

  python3 test_matrices_fast/compare_hybrid_isvd.py

Key transform (for completeness):
    C = Vt @ Vt_exact[:k, :]^T   # saved directly in canonical_angles file
    align_i = sqrt(max(i - ||C[:, :i]||_F^2, 0))   # Frobenius residual

### 6g. Single-shot score-component diagnostic

  python3 diag_hybrid_stocks_ls002.py

Runs once on kernel_stocks N=1000 at ls=0.02 and ls=0.2236, with a
simulated 10-block streaming state, and prints per-direction
gain² and φ for oracle / iSVD-pick / random candidates. Useful as a
fast sanity check of whether the combined score is being driven by
gain² alone on a new matrix.
