Joint Stiefel optimizer progress summary
========================================

Context
-------
Main file:
  cex_restricted_space_probe.py

New fair-comparison helper:
  compare_joint_same_state.py

The original restricted optimizer selected rank-r vectors sequentially/greedily.
We added a true joint Stiefel option that optimizes all columns together for

  max_{Z'Z = I} sum_j F(z_j)

using stacked gradients G, Stiefel tangent projection

  Xi = G - Z sym(Z'G),

a joint step, and polar/SVD retraction.


Implemented options
-------------------
Existing greedy path remains default:

  --basis-selection greedy

Joint rank-r optimizer:

  --basis-selection joint

Joint solver choices:

  --joint-solver riemannian
  --joint-solver slsqp

The SLSQP option is a constrained quasi-Newton/SQP refinement over Z'Z = I
using exact objective gradients. It did not improve alignment in our tests.

Warm-start and perturbation options:

  --joint-warm-start-greedy
  --joint-warm-start-rotations N
  --joint-warm-start-rotation-angle ANGLE
  --joint-warm-start-perturbations N
  --joint-warm-start-perturb-scale SCALE

Oversampling/compression options:

  --joint-oversample K
  --joint-oversample-rotate svd

Oversampling solves for rank + K joint columns, then rotates/compresses back
to rank using an SVD inside the oversampled span.

Best high-random command
------------------------
This produced mean_align ~= 0.999259 under the projection-norm convention:

python cex_restricted_space_probe.py \
  --matrix static-cex --mode restricted --dtype float64 --carry left \
  --reduced-optimizer cex --expansion-direction residual \
  --n 128 --win 32 --rank 2 --preset cex-replicate \
  --q0 4 --qmax 32 --krylov-depth 2 --residual-tol 1e-4 \
  --expansion-maxit 8 --num-restarts 64 --maxit 1000 --tol 1e-10 \

Fair same-state comparison
--------------------------
Because streaming state changes the problem, we added:

  compare_joint_same_state.py

It freezes one reference previous state and compares candidate optimizers on
the exact same block with the exact same state_prev, M_gain, and A_block.

Default reference state:
  old greedy through prior blocks.

Run final-block comparison:

  python compare_joint_same_state.py --target-block 3

Current interpretation
----------------------
1. The true joint Stiefel optimizer is implemented and works.
2. Tightening tolerances does not fix the old greedy failure.
3. SLSQP/quasi-Newton solves the same score objective more cleanly but does
   not improve alignment.
4. Rotations and local tangent perturbations around greedy warm starts do not
   beat the unrotated greedy warm start.
5. Oversample=1 + SVD rotate can improve whole-stream alignment to 0.9850, but
   it breaks the per-column score stationarity diagnostics after compression.
6. High-random joint with expansion path can get close to perfect alignment
   (0.9993), but only by changing the streaming trajectory and at high cost.
7. Fair same-state comparisons show that on a fixed previous state, all
   score-based final-block optimizers mostly agree.


Recommended next experiments
----------------------------
1. Extend compare_joint_same_state.py to allow the reference previous state to
   be generated by high-random joint through rows 1:96. Then compare all
   final-block optimizers on that high-random previous state.

2. Run a budget sweep for high-random joint whole-stream:
     num_restarts in {16, 32, 64}
     maxit in {250, 500, 1000}
     post_expansion_maxit in {120, 250, 500}
   Goal: find the cheapest setting that still gets align near 0.04.

3. Track per-block carried-state quality:
     alignment of state["V"] after each block,
     candidate score sums,
     subspace dimension,
     grad_perp_ratio.
   This will show where the high-random trajectory diverges beneficially from
   greedy.

4. Add a diagnostic alignment selector among candidate frames using V_exact.
   This is not for production, but it can answer whether good-alignment
   candidates are being generated and rejected by score.
